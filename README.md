# EventSentry 事件参谋

> 面向个人投资者的**投资事件情报 Agent**。看清事件最初来源、事实变化、证据冲突、当前状态以及与关注标的的关系。
>
> **实际可运行版本：** Python FastAPI + SQLite + iFinD/同花顺 MCP + GLM-4.6
> **最后同步：** 2026-10-09（v2.2.0）

---

## 目标用户

**个人投资者**（持股 1–20 只，日均盯盘 < 30 分钟）

- **痛点**：同一事件的信息散落在公告、新闻、研报、股吧，难以看清全貌；传闻和事实混为一谈；错过关键节点
- **场景**：开盘前扫一眼持仓有无重大事件；盘中看到异动想快速判断可信度；盘后复盘某事件的来龙去脉
- **画像**：非专业投研人员，需要结构化、分层、带时间线的事件情报，而非原始信息堆砌

## 核心设计

### 三 Tab 结构（移动端优先）

```
┌─────────────────────────────────────┐
│  [发现]    [参谋]    [我的]          │
│  信息流    对话Agent   个人主页       │
└─────────────────────────────────────┘
```

| Tab | 定位 | 核心能力 |
|-----|------|----------|
| **参谋**（首页） | 对话式事件查询 | 自然语言提问 → Agent 真实调用 iFinD 工具 → 返回基于真实数据的分析与可追溯引用 |
| **发现** | 主动信息流 | 事件卡片列表，支持搜索、利好/利空筛选、刷新、加载更多 |
| **我的** | 个人中心 | Agent 运行状态面板、持仓管理、事件订阅、风险偏好、通知中心 |

### 核心交付物：事件判断卡片

**Face（摘要态）**：影响标签（利好/利空/中性/风险）+ 状态标签（官方确认/媒体验证/未证实传闻/官方否认/实质落地/已过期）+ 时间线迷你图 + 一句话摘要

**Back（详情态）**：
- **证据权重条**：按 T0（公告）/ T1（媒体）/ T2（研报）/ T3（传闻）分层可视化
- **版本演化链**：每次状态变化一条版本记录，标注变化类型（更新/否认/更正/过期）+ 触发的规则编号
- **事件脉络**：时间线节点 + 分层证据详情
- **其他说法**：演化方向（概率 + 支撑 + 风险）+ 独立传闻区（标注"未证实"）
- **数据来源标注**：抓取时间 / 披露时间 / 事件时间 + iFinD 来源标识

### 四时间轴

| 时间类型 | 字段 | 含义 |
|----------|------|------|
| **事件发生时间** | `event_time` | 事情实际发生的日期 |
| **披露时间** | `disclosure_time` | 信息公开的日期 |
| **抓取时间** | `crawl_time` | 系统采集的时刻 |
| **更新时间** | `updated_at` | 事件最后状态变化的时间 |

### 版本演化

同一事件随新证据/否认/更正/过期而演化，每次跃迁生成版本快照（`event_versions`），记录：
- 变化类型：`update` / `deny` / `correct` / `expire`
- **触发的规则编号**（如 `Rule 3`）与变化原因 —— 保证结论可追溯

## AI 角色：3 个 Agent + 1 个定时任务

> 详细定义见 [`AGENTS.md`](AGENTS.md)

### ① Collector Agent（感知层，每 30 分钟）
- **模型**：glm-4-flash（不可用时自动降级 glm-4.6）
- **职责**：iFinD 抓取 → 指纹去重 → 要素预抽取 → 写入 `raw_messages` 队列
- **文件**：`server/agents/collector_agent.py`

### ② Analyst Agent（认知层，核心）
- **模型**：glm-4.6
- **职责**：
  1. **语义分析**：主题、证据类型（事实/观点/推测/传闻）、语义（确认/否认/落地）、来源分级（T0-T3）
  2. **同一事件聚类**：判断消息归属已有事件 or 新建（受 18 项规范主题表约束，避免过度拆分）
  3. **调用规则层状态裁决**（LLM 只"看懂"，裁决交规则）
  4. **卡片生成** + **合规扫描** + **版本快照** + **通知推送**
- **文件**：`server/agents/analyst_agent.py`

### ③ Conversation Agent（参谋，实时）
- **模型**：glm-4.6
- **职责**：对话 + 工具调用（查公告 / 查行情 / 查财务 / 查公司资料），所有事实来自 iFinD 真实返回
- **文件**：`server/agent.py`

### ④ Reflector（反思层，**定时任务非 Agent**，每日 02:00）
- **模型**：无（确定性统计）
- **职责**：命中率校准、争议标记、过期检查
- **文件**：`server/reflector.py`

### 确定性规则层（无 LLM，可追溯的基石）

| 模块 | 文件 | 说明 |
|------|------|------|
| **事件状态机** | `server/rules/state_machine.py` | 6 状态 13 规则，每次跃迁记录触发的规则编号 |
| **合规审查** | `server/rules/compliance.py` | 红线词扫描、T3 必须标注"未证实"、禁止精确百分比 |

**设计边界**：LLM 负责"看懂"（语义判断），规则负责"裁决"（确定性产出）。这样既保证语义准确，又保证结论可复现、可审计。

### 完整证据演化链（已打通）

事件从「传闻」到「官方确认 / 否认 / 实质落地 / 过期」的完整演化，**已用真实案例演示，覆盖全部 6/6 个状态**：

| 事件 | 完整演化链 | 触发规则 |
|------|-----------|----------|
| **腾讯控股 · AI进展** | 传闻(3-02) → 媒体验证(6-15) → **官方确认**(8-12) | Rule 1 → 4 → 7 |
| **中芯国际 · 并购重组** | 官方确认(2-25) → **实质落地**(5-12) | Rule 3 → 9 |
| **五粮液 · 并购重组** | 传闻(2-18) → **官方否认**(2-19) → 已过期 | Rule 1 → 6 → 11 |
| **比亚迪 · 监管问询** | 传闻(5-08) → **官方否认**(5-09) → 已过期 | Rule 1 → 6 → 11 |
| **宁德时代 · 技术进展** | 传闻(7-07) → 媒体验证(7-08) | Rule 1 → 4 |

每个事件详情页可查看**完整版本演化链**（每次跃迁一条记录，标注触发的规则编号与变化原因）。
注：五粮液/比亚迪事件因否认已超 7 天无新证据，被规则正确判为「已过期」——这本身就是状态机闭环的体现。

### ⚠️ 数据边界（如实披露）

1. **iFinD 新闻接口返回为空**：`search_news` / `search_trending_news` 实测均 0 条。
   因此 T1（媒体）/ T2（研报）/ T3（传闻）证据改由 **Serper（Google Search API）自动采集**（`server/media_search_collector.py`）：
   - 对 35 只跟踪标的自动搜索，按**确定性域名分级表**判定层级（财新/证券时报/界面/36氪 → T1；股吧/雪球/微博/知乎 → T3）
   - 实测一次采集：`fetched 514 · new 145（T1 媒体 72 + T3 传闻 73）`
   - ✅ **已全自动**，无需人工干预
2. **未接入扶摇**：本环境无扶摇 skill / 密钥。其角色（行情/财务/估值）由 iFinD 股票工具承担，**已实测可用**。
3. **数据规模**：跟踪 **35 只标的**，iFinD 公告 + Serper 媒体/传闻双源采集，支持发现页**无限滚动**。
4. **「已过期」状态**需时间自然流逝才能触发。

## 快速启动

### 环境要求
- Python ≥ 3.10
- 依赖：`pip install fastapi uvicorn requests`

### 启动步骤

```bash
# 1. 安装依赖
pip install fastapi uvicorn requests

# 2. 采集真实数据（从 iFinD/同花顺拉取）
cd server
python _run_pipeline.py       # 采集 Agent → 分析 Agent 完整流水线

# 3. 启动服务（自动开启定时调度）
python main.py
# 访问 http://localhost:3000
```

### 环境变量（可选）

| 变量 | 默认 | 说明 |
|------|------|------|
| `ENABLE_SCHEDULER` | `1` | 设为 `0` 关闭定时调度 |
| `COLLECT_INTERVAL_MIN` | `30` | 采集间隔（分钟） |
| `REFLECT_HOUR` | `2` | 每日反思时刻 |
| `COLLECT_LOOKBACK_DAYS` | `30` | 采集回溯天数 |

### 开发辅助脚本

| 脚本 | 用途 |
|------|------|
| `server/_run_pipeline.py` | 跑完整流水线（采集+分析） |
| `server/_inspect.py` | 只读检查数据库状态（**严禁写入**） |
| `server/_rebuild.py` | 清空事件层、保留原始消息，供重建 |
| `server/_e2e.py` | 端到端验证 |

## 已知边界与未做事项

### 已知边界（当前版本明确不做）

1. **不做股价预测**：不预测涨跌幅、不给目标价，仅展示事件后历史统计
2. **不做投资建议**：合规规则层自动扫描并阻塞"买入/卖出/加仓/减仓/目标价"等红线词
3. **不做非公开信息处理**：仅处理公开数据源
4. **不做法律合规判断**：仅引用监管原文
5. **单用户开发模式**：`/api/me` 固定 user_id=1，未接入 Kimi OAuth
6. **仅支持 A 股 / 港股**：不支持美股、期货

### 未做事项

| 事项 | 阻塞原因 |
|------|----------|
| **T1/T2/T3 证据分层演化** | iFinD 新闻接口返回为空，**需确认账号权限**或接入 WebSearch 抓取媒体源 |
| **扶摇数据源** | 环境无扶摇 skill / 密钥，**需用户提供** |
| **真实用户登录** | 需 Kimi OAuth 的 `APP_ID` / `APP_SECRET` |
| 实时推送（WebSocket / SSE） | 当前为轮询 |
| 跨标的行业事件关联 | 当前仅单标的事件 |
| 演示视频 / AI 验证记录 | 提交材料，待产出 |
| 反思任务完整周期验证 | 调度已就位，需经一个自然日验证 |
