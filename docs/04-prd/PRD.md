## 一、产品总览

### 1.1 一句话定义

面向个人投资者的**投资事件情报 Agent App**，通过底部三 Tab 提供：①自然语言对话查询事件（参谋）②主动推送股市大事件（发现）③个人信息与持仓管理（我的）。核心交付物是"事件判断卡片"——把同一标的同一主题的分散消息聚合成带状态标签、时间线、证据分层、演化预测的信息单元。

### 1.2 三 Tab 结构

```
┌─────────────────────────────────────┐
│  顶部标题栏                          │
├─────────────────────────────────────┤
│                                     │
│           【内容区】                  │
│                                     │
│                                     │
├─────────────────────────────────────┤
│  [发现]    [参谋]    [我的]          │
│   👁        💬        👤             │
│  信息流    对话Agent   个人主页       │
└─────────────────────────────────────┘
```

**参谋 Tab 为首页默认页**——因为对话是用户使用本产品最核心的动机（"我想问这只股票怎么样了"）。

## 二、功能一：参谋 Tab（对话 Agent）

### 2.1 入口与首屏

用户首次打开 App，进入参谋 Tab，界面如下：

```
┌─────────────────────────────────────┐
│  EventSentry 事件参谋                │
├─────────────────────────────────────┤
│                                     │
│  💬 我是你的事件参谋                  │
│                                     │
│  我可以帮你：                        │
│  • 追踪你持仓/关注股票的最新事件       │
│  • 理清同一事件的来龙去脉与可信度      │
│  • 提示你下一步该关注什么节点          │
│                                     │
│  你可以这样问我：                     │
│  ┌─────────────────────────────────┐│
│  │ "帮我看看腾讯最近有什么大事"     ││
│  │ "宁德时代最近有没有影响股价的事" ││
│  │ "最近股市有什么值得关注的事件"   ││
│  └─────────────────────────────────┘│
│                                     │
├─────────────────────────────────────┤
│  💬 输入股票名称或事件关键词...       │
└─────────────────────────────────────┘
```

**推荐提问可点击**，点击后直接发送给 Agent，降低输入门槛。

### 2.2 对话交互

用户输入自然语言，Agent 理解意图后返回**事件判断卡片**。

**支持意图：**

| 用户说法 | Agent 行为 |
|---------|-----------|
| "帮我看看腾讯最近有什么大事" | 检索腾讯近 30 天活跃事件，返回卡片列表 |
| "腾讯和 DeepSeek 合作是真的吗" | 定位到具体事件，返回该事件卡片 |
| "最近股市有什么热点" | 返回站内热度最高的事件卡片（跨标的） |
| "我持仓的票有没有风险" | 检索用户持仓标的的风险类事件 |
| "这个事件后续会怎样" | 基于当前证据给出演化方向（Back 内容） |

**V1 实际实现：** 前端关键词搜索（匹配 ticker_name、theme、headline），返回预置事件列表中的匹配项。非真正的 LLM Agent，但交互形态一致。

**Agent 回复形态：** 优先返回卡片；若用户问的是开放性问题，先给一段总结再推荐相关卡片。

### 2.3 事件判断卡片（核心交付物）

对话中返回的卡片，与发现 Tab 的卡片为**同一组件**。

**卡片结构（正面/默认态）：**

```
┌─────────────────────────────────────┐
│  [利好]  腾讯控股 · 微信接入DeepSeek  │  ← 影响状态标签 + 事件主名称
│                                     │
│  事件进展：                          │
│  ●────●────●────●────●              │  ← 时间线节点（圆点连线）
│  1月   2月   3月   4月  当前        │  ← 节点时间标注
│  传闻→测试→公告→深化→进行中         │  ← 节点状态简述
│                                     │
│  当前节点：官方已确认（测试阶段）      │  ← 最新状态一句话
│  建议关注：3月15日年报业绩会          │  ← 下一步节点
│                                     │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  可信度：高  ·  3条核心证据          │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│                                     │
│  [查看详细脉络]  [其他说法 →]        │  ← 两个入口
└─────────────────────────────────────┘
```

**卡片元素详细规格：**

| 元素 | 说明 |
|------|------|
| **影响状态标签** | 左上角彩色标签：`[利好]` `[利空]` `[中性]` `[风险]` `[待验证]`。由最高权重证据决定。 |
| **事件主名称** | 一句话概括，格式"标的 · 核心动作"。如"腾讯控股 · 微信接入DeepSeek" |
| **时间线节点** | 按披露时间排列的**关键状态跃迁节点**，不是日记式每日消息。节点间等距。 |
| **时间折叠规则** | 若事件跨度 > 1 年，早期节点自动折叠为"··· 2023年 ···"，点击展开。卡片默认展示近 6 个月。 |
| **当前节点** | 最新状态的一句话描述，如"官方已确认（测试阶段）" |
| **建议关注** | 推断的下一关键时点，如"3月15日年报业绩会"，可点击订阅提醒 |
| **可信度** | `高/中/低` + 核心证据数量，点击展开证据链 |
| **查看详细脉络** | 点击进入事件详情页（全屏页面） |
| **其他说法 →** | 展开卡片背面或进入详情页第二个 Tab |

### 2.4 事件详情页（点击卡片进入）

全屏页面，底部返回按钮。

**页面结构：**

```
┌─────────────────────────────────────┐
│  ← 返回               [关注此事件]   │
├─────────────────────────────────────┤
│  [利好]  腾讯控股 · 微信接入DeepSeek  │  ← 顶部固定
│                                     │
│  Tab 切换：[事件脉络]  [其他说法]      │
├─────────────────────────────────────┤
│                                     │
│  【Tab 1：事件脉络】                  │
│                                     │
│  时间线（纵向）：                     │
│                                     │
│  ●───── 2024年1月15日               │
│  │      [传闻出现] 股吧/雪球          │
│  │      "微信将接入某 AI 大模型"       │
│  │      来源：匿名传闻  可信度：低      │
│  │                                    │
│  ●───── 2024年2月8日                │
│  │      [媒体验证] 财新/一财           │
│  │      "微信灰度测试接入 DeepSeek"    │

│                                     │
│  ────────────────────────────────── │
│  证据总览：                           │
│  T0 官方披露：1条  T1 权威媒体：2条   │
│  T2 研报观点：3条  T3 市场传闻：5条   │
│  （点击分类可展开查看原文）            │
│                                     │
├─────────────────────────────────────┤
│  【Tab 2：其他说法】                  │
│                                     │
│  基于当前证据，市场的其他判断：        │
│                                     │

│  概率：中高                          │
│  支撑：2家权威媒体确认测试进展顺利      │
│  风险：正式协议尚未签署               │
│                                     │
│  [可能方向B] 仅为防御性测试，无实质   │
│  概率：中                            │

│                                     │
└─────────────────────────────────────┘
```

**Tab 1（事件脉络）规则：**
- 纵向时间线，节点按披露时间排序；
- 每个节点显示：时间、状态标签（如[传闻出现]）、来源层级、内容摘要、可信度；
- 超过 1 年的旧节点折叠，显示"··· 2023年及更早 ···"，点击展开；
- 底部证据总览：按 T0/T1/T2/T3 分层统计，点击分类展开该层级全部证据原文。

**Tab 2（其他说法）规则：**
- 展示 2-3 个"基于当前证据缺口"的合理演化方向；
- 每个方向包含：场景描述、概率区间（高/中/低）、支撑证据、风险点；
- **传闻区独立列出**：明确标注为"市场传闻"，与"合理推演"视觉区隔，显示来源和可信度；
- 不预测股价涨跌，只描述事件本身的几种可能走向。

### 2.5 对话追问（卡片下方的对话区）

用户看完卡片后可以继续追问，Agent 基于当前事件上下文回答。

**快捷追问按钮（动态生成，基于当前卡片内容）：**
- "为什么可信度是 High？"
- "这和腾讯游戏业务有关吗？"
- "如果 3 月 15 日没进展会怎样？"
- "历史上类似事件后来怎样了？"

**自由输入示例：**
- "帮我对比下阿里有没有类似动作" → 返回对比卡片
- "减仓的话有什么风险" → "我无法提供投资建议。可以告诉你当前事件的风险等级：合作未签正式协议，存在终止可能"

**合规红线：** 任何买卖建议、目标价、涨跌预测 → 固定拒答模板。

## 三、功能二：发现 Tab（信息流）

### 3.1 定位

主动推送股市大事件的信息流页。用户不需要输入，打开即看。

### 3.2 推送逻辑

```
用户打开发现 Tab
   ↓
判断用户是否有"关注标的"
   ├── 有关注 → 推送"关注标的的最新活跃事件"（按更新时间倒序）
   └── 无关注 → 推送"站内热度最高的事件"（跨标的，按浏览量+讨论量排序）
```

**排序规则：**
1. 用户关注标的的、24 小时内有状态跃迁的事件（置顶）
2. 用户关注标的的、有新增证据但无跃迁的事件
3. 站内热度最高的事件（全站浏览量 Top 10）
4. 系统推荐的市场重大事件（如大型 IPO、监管新政）

**V1 实际实现：** 展示预置的 6 个事件卡片，按 updated_at 倒序排列。支持搜索（ticker_name、theme、headline）和按 nature（positive/negative/risk/neutral）筛选。

### 3.3 信息流卡片

卡片形式与参谋 Tab 返回的卡片**同一组件**，但信息流中是缩略态：

```
┌─────────────────────────────────────┐
│  [利好]  腾讯控股 · 微信接入DeepSeek  │
│                                     │
│  一句话：微信测试接入 DeepSeek，       │
│          公司确认探索中               │
│                                     │
│  建议关注：3月15日年报业绩会          │
│  最新节点：官方已确认（测试阶段）      │
│                                     │
│  [查看脉络]  [关注此事件]             │
└─────────────────────────────────────┘
```

**与参谋 Tab 卡片的区别：**
- 信息流卡片默认折叠时间线，只显示"一句话摘要 + 最新节点 + 建议关注"；
- 点击进入同一个事件详情页（展开时间线 + 其他说法 Tab）。

### 3.4 操作

- **点击进入详情：** 进入与参谋 Tab 完全一致的事件详情页（脉络 Tab + 其他说法 Tab）；
- **关注此事件：** 订阅后，该事件状态跃迁时推送给用户；
- **下滑刷新：** 加载更多事件；
- **顶部筛选：** 可按"利好/利空/风险/全部"过滤。

## 四、功能三：我的 Tab（个人主页）

### 4.1 页面结构

```
┌─────────────────────────────────────┐
│  个人主页                            │
├─────────────────────────────────────┤
│                                     │
│  [头像]  用户昵称                     │
│  ID: 12345678                       │
│  [稳健型] [持仓 2]                   │
│                                     │
│  ─────── 我的持仓 ───────            │
│  腾讯控股    00700.HK    [×]        │
│  宁德时代    300750      [×]        │
│  [+ 添加持仓]                        │
│                                     │
│  ─────── 我的关注 ───────            │
│  关注事件：12 个                      │
│  关注标的：5 个                       │
│                                     │
│  ─────── 偏好设置 ───────            │
│  风险偏好：稳健                       │
│  消息通知：开启                       │
│                                     │
│  ─────── 其他 ───────                │
│  免责声明                            │
│  退出登录                            │
│                                     │
└─────────────────────────────────────┘
```

### 4.2 功能模块

| 模块 | 内容 |
|------|------|
| **我的持仓** | 增删改股票代码 + 成本价（选填）。用于参谋 Tab 的"我持仓的票有没有风险"查询，以及发现 Tab 的定向推送 |
| **我的关注** | 关注的事件列表 + 关注的标的列表。可取消关注 |
| **风险偏好** | 保守/稳健/积极 三档。影响：传闻层默认折叠程度、通知频率、概率表述方式 |
| **免责声明** | 常驻入口，可查看完整版 |
| **通知设置** | 开启/关闭 P0/P1 推送 |

**V1 实际实现：**
- 注册：输入昵称 → 生成 user_id → 写入 localStorage
- 持仓：添加（ticker + ticker_name）/ 删除（holding_id）
- 关注：事件订阅（event_id）/ 标的订阅（ticker）
- 偏好：risk_level（conservative/moderate/aggressive）、notification_enabled
- 持久化：全部基于 localStorage，key 前缀 `eventsentry_`

### 4.3 首次引导（与参谋 Tab 首屏联动）

首次打开 App，在参谋 Tab 首屏的对话引导中，若用户点击了"帮我看看腾讯最近有什么大事"，系统自动将"腾讯"加入"我的关注标的"，后续发现 Tab 会定向推送腾讯事件。

## 五、非功能需求

### 5.1 合规（阻塞性红线）

- 任何用户可见文案不得含：买入、卖出、持有建议、加仓、减仓、目标价、必涨、稳赚、抄底、逃顶——每日自动扫描；
- 卡片上的"建议关注"仅指"信息关注节点"，非"建议操作"；
- T3 传闻层必须标注"未证实"；
- 常驻免责声明入口；
- 涉及具体个人的内容仅引用公开披露，不做指控性推断。

### 5.2 性能

- 首屏加载 ≤ 2 秒（纯静态资源，gzip 后 JS ≤ 200KB）
- 事件详情页打开 ≤ 300ms（前端路由，无网络请求）
- 搜索响应 ≤ 100ms（前端内存过滤）

### 5.3 时间戳处理

- 事件脉络轴以**披露时间**为准；
- 事件发生时间（如"上周签订"）在节点详情中标注；
- 旧闻重发：fingerprint 去重，不重复计算；
- 超过 1 年的节点自动折叠。

### 5.4 部署

- **目标平台：** GitHub Pages（纯静态托管）
- **构建输出：** `dist/` 目录（index.html + assets/）
- **配置要求：** `vite.config.ts` 中设置 `base: '/repo-name/'`

| # | 问题 | 建议 |
|---|------|------|
| 1 | Back 卡片概率是否显示精确百分比 | V1 用"高/中/低"，V2 再上数字 |
