# EventSentry 事件参谋 V1.0

> 一个围绕"同一事件"识别、合并与版本演化的移动端 AI Agent 产品。帮助个人投资者看清事件最初来源、事实变化、证据冲突、当前状态以及与关注标的的关系。
> 
> **线上地址：** https://lmjl4rqqj3ogy.ok.kimi.link

---

## 一、目标用户

**核心用户：** 中国 A 股及港股市场的个人投资者（散户），持仓规模 5-50 万，不具备专业投研团队支持。

**典型画像：**
- 持有 1-5 只股票，每天被 App 推送、微信群、股吧的碎片化信息包围；
- 无法判断"今天这条消息"和"上周那条传闻"是否是同一件事；
- 在"传闻-公告-大V反驳-券商研报"的信息洪流中，分不清该信谁；
- 不是想要"更多新闻"，而是想要"这件事现在到底进行到哪一步了"。

**用户核心诉求：**
1. **节省信息收集时间** —— 同一事件的几十条消息自动聚合成一张卡片；
2. **降低决策门槛** —— 事件当前状态、可信度、下一步关注点，3 秒可见；
3. **及时跟进事件** —— 事件性质发生变化时主动推送，不错过关键转折。

## 二、产品形态

**移动端 Web App，底部三 Tab 导航，适配手机浏览器直接访问。**

| Tab | 名称 | 定位 | 核心交互 |
|-----|------|------|---------|
| **发现** | 左 | 股市大事件信息流 | 被动接收：打开即看，系统主动推送 |
| **参谋** | 中（首页默认） | 对话 Agent | 主动查询：自然语言输入，返回判断卡片 |
| **我的** | 右 | 个人主页 | 管理持仓、关注列表、偏好设置 |

### 2.1 参谋 Tab —— 对话 Agent（核心入口）

用户打开 App 默认进入参谋页，可与 Agent 自然语言对话。

**首次进入引导：**
```
💬 我是你的事件参谋
我可以帮你：
• 追踪你持仓/关注股票的最新事件
• 理清同一事件的来龙去脉与可信度
• 提示你下一步该关注什么节点

你可以这样问我：
• "帮我看看腾讯最近有什么大事"
• "宁德时代最近有没有影响股价的事"
• "最近股市有什么值得关注的事件"
```

**Agent 回复形态：** 事件判断卡片。

**卡片结构（已实现）：**
```
┌─────────────────────────────────────┐
│  [利好]  腾讯控股 · 微信接入DeepSeek  │  ← 影响状态标签 + 事件主名称
│                                     │
│  事件进展：                          │
│  ●────●────●────●────●              │  ← 时间线节点（关键跃迁）
│  1月   2月   3月   4月  当前        │
│  传闻→测试→公告→深化→进行中         │
│                                     │
│  当前节点：官方已确认（测试阶段）      │
│  建议关注：3月15日年报业绩会          │
│                                     │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  可信度：高  ·  3条核心证据          │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│                                     │
│  [查看详细脉络]  [其他说法 →]        │
└─────────────────────────────────────┘
```

**详情页双 Tab（已实现）：**
- **Tab 1（事件脉络）：** 纵向时间线，按披露时间排列状态跃迁节点（非日记式每日消息），超过 1 年折叠；底部按 T0/T1/T2/T3 分层展示全部证据。
- **Tab 2（其他说法）：** 2-3 个基于证据缺口的演化方向 + 市场传闻区（独立标注"未证实"）。

### 2.2 发现 Tab —— 信息流

主动推送股市大事件。

**推送逻辑（当前实现）：**
- 展示基于 iFinD 真实公告数据构建的 6 个核心事件卡片；
- 支持按"利好/利空/风险/全部"过滤；
- 支持搜索股票名称、代码、事件主题。

**信息流卡片：** 与参谋 Tab 同一组件的缩略态，显示"事件标签 + 最新节点 + 更新时间"，点击进入同一详情页。

### 2.3 我的 Tab —— 个人主页

- **我的持仓**：增删改股票代码（localStorage 持久化）
- **我的关注**：关注的事件列表 + 关注的标的列表
- **风险偏好**：保守/稳健/积极 三档（localStorage 持久化）
- **用户注册**：首次进入弹出注册框，输入昵称即完成注册
- **免责声明、退出登录**

## 三、核心设计

### 3.1 "同一事件"定义

**同一事件 = 同一标的（股票/公司）+ 同一主题（核心动作/第三方/影响逻辑一致）**

- **合并：** 同一标的、同一收购对象，传闻出现 → 公告否认 → 新证据指向同一对象；
- **拆分：** 同一标的、不同主题（腾讯 AI 布局 vs 腾讯游戏出海）；
- **主题偏移拆分：** 传闻核心对象变化（"收购 A 公司"→"收购 B 公司"）→ 拆分为两个独立事件；
- **时间窗口：** 同一主题下 30 天内的关联消息默认聚合；超过 30 天视为新事件。

### 3.2 消息可信度阶梯

| 层级 | 来源 | 定位 |
|------|------|------|
| T0 事实层 | 交易所公告、监管文件、公司正式披露 | 主心骨，优先采信 |
| T1 验证层 | 财新/第一财经/Reuters、交易所互动易 | 辅助证实 |
| T2 观点层 | 券商研报、知名机构分析 | 推演视角，不代表事实 |
| T3 传闻层 | 股吧、自媒体、群聊截图、匿名消息 | "市场有这种声音" |

**呈现规则：** T0/T1 进入"核心证据区"默认展开；T2 折叠但可见；T3 默认折叠，用户手动展开，必须标注"未证实"。

### 3.3 状态演化（非时间线，是状态跃迁链）

```
未证实传闻 → 媒体验证 → 官方确认 → 实质落地
     ↓            ↓           ↓
   传闻消失     官方否认     否认被推翻
     ↓            ↓
   事件过期     事件过期
```

**通知规则：** 仅在状态跃迁时推送给用户，非跃迁的新消息静默收录。

### 3.4 概率与辅助判断

- **正面不给精确百分比**，只给"高/中/低"可信度 + 状态标签；
- **"其他说法"Tab** 展示方向概率（高/中/低），来源：渠道历史准确率 × 渠道评级 × 用户风险偏好；
- **绝不输出"买入/卖出/目标价"**，只输出"事件状态 + 风险 + 关注节点"。

## 四、AI 角色

### 4.1 Agent 类型：3 个 Agent 协作（设计蓝图）

| Agent | 职责 | 触发方式 |
|-------|------|---------|
| **① Collector（感知 Agent）** | 多源数据抓取、去重、清洗、要素预抽取 | cron 每 5 分钟 |
| **② Analyst（判断 Agent）** | 语义聚类、证据分级、状态机裁决、卡片生成、对话应答 | 队列消费 + 用户对话 |
| **③ Reflector（反思 Agent）** | 每日误判回溯、渠道命中率校准、高争议标记 | cron 每日 02:00 |

**V1 实际实现说明：** V1 为纯前端静态应用，Agent 能力通过构建期脚本（Python + iFinD MCP）离线实现数据收集与结构化，前端通过关键词搜索模拟 Analyst 的查询能力。完整 Agent 流水线为 V2 后端化目标。

### 4.2 AI 能力边界

**AI 做（能力圈内）：**
- 自然语言理解：从公告/新闻/研报/股吧中抽取事件要素
- 语义聚类：基于 Embedding + 规则判断两条消息是否同一主题
- 证据分层：根据来源类型和文本特征自动分级 T0-T3
- 摘要生成：把多条消息浓缩成卡片的一句话结论
- 对话上下文：基于当前事件状态回答用户追问，引用具体证据

**AI 不做（能力圈外）：**
- 股价预测、目标价、买卖点建议
- 使用"一定""必然""稳赚"等绝对化表述
- 将传闻当作事实陈述
- 询问或处理用户的账户密码、资金量等敏感信息

### 5.3 数据源与数据获取

**已接入数据源（V1）：**

| 数据源 | 类型 | 用途 | 获取方式 |
|--------|------|------|---------|
| iFinD MCP | 公司公告、业绩预告 | **主数据源**，事件识别与证据提取 | 构建期 Python 脚本调用 |

**数据获取流程（构建期）：**
```
1. Python 脚本调用 iFinD MCP: ifind_get_stock_announcement(ticker, start_date, end_date)
2. 解析 CSV 返回结果，提取关键公告
3. 人工/规则结构化：聚合同一主题公告 → 生成时间线节点 → 分级 T0-T3
4. 输出为 src/data/events.ts（TypeScript 模块）和 src/data/events.json
5. Vite 构建时直接打包进产物
```

**V1 数据边界：**
- 当前包含 6 个结构化事件，覆盖宁德时代、比亚迪、中芯国际、五粮液、腾讯控股
- 事件数据基于 2025 年 7 月-10 月真实公告构建
- 每条证据标注来源、日期、可信度层级

## 六、快速开始

### 6.1 本地开发

```bash
# 克隆仓库
git clone https://github.com/your-org/invest-intel-agent.git
cd invest-intel-agent

# 安装依赖
npm install

# 启动开发服务器
npm run dev

# 访问 http://localhost:5173
```

### 6.2 构建部署

```bash
# 生产构建
npm run build

# 构建产物位于 dist/ 目录
# - dist/index.html
# - dist/assets/（JS、CSS、静态资源）
```

### 6.3 GitHub Pages 部署

**方式一：手动部署（gh-pages 分支）**

```bash
# 1. 确认 vite.config.ts 中 base 路径
export default defineConfig({
  base: '/invest-intel-agent/',  // 根据仓库名调整
  // ...
})

# 2. 构建
npm run build

# 3. 将 dist/ 推送到 gh-pages 分支
git subtree push --prefix dist origin gh-pages
```

**方式二：GitHub Actions 自动部署**

创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

然后在仓库 Settings → Pages → Source 中选择 "GitHub Actions"。

## 七、已知边界与未做事项

### 7.1 V1 已知边界（当前版本）

1. **纯静态应用**：无后端服务，无实时数据更新，事件数据在构建期固化；
2. **用户系统 localStorage**：注册信息、持仓、偏好仅存储在本地浏览器，换设备/清缓存丢失；
3. **Agent 对话能力**：当前为前端关键词搜索匹配，非真正的 LLM 对话 Agent；
4. **事件覆盖范围：** 6 个预置事件（宁德时代×2、比亚迪、中芯国际、五粮液、腾讯），需手动扩展；
5. **数据实时性：** 依赖构建期数据，非实时推送；盘中异动类事件无法即时反映；
6. **跨市场：** 优先 A 股与港股；美股标的若通过数据源可获取则支持。

### 7.2 V2 规划

- [ ] 接入后端服务（Hono + tRPC + PostgreSQL），实现实时数据采集与 Agent 对话
- [ ] 完整 Collector/Analyst/Reflector Agent 流水线
- [ ] 研报观点的"看多/看空/中性"情感方向自动识别与冲突标注
- [ ] 用户自定义渠道权重（对单个自媒体/分析师设置"特别关注"或"屏蔽"）
- [ ] 行业政策事件的跨标的自动关联
- [ ] 事件与行情的深度耦合（在状态节点上叠加 K 线 mini 图）
- [ ] 多模态输入（支持用户上传群聊截图，OCR 提取后进入传闻层）

### 7.3 合规边界

- 本产品不提供证券投资咨询服务，不输出具体证券的买入/卖出/持有建议；
- 所有"建议关注"字样均指"信息关注建议"（如"建议关注 3 月 15 日节点"），非投资建议；
- 界面显著位置披露"本产品的判断基于公开信息整理，不构成投资建议，投资有风险，决策需独立"；
- 涉及用户持仓数据仅本地存储，不用于产品外的任何商业目的。
