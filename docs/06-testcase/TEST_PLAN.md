### TC-004: 事件状态演化与时间戳处理

**测试数据：**

| 消息 | 事件发生时间 | 披露时间 | 抓取时间 | 类型 |
|------|------------|---------|---------|------|
| 消息 A | 2024-03-01 | 2024-03-01 | 2024-03-01 10:00 | T3 股吧 |
| 消息 B | 2024-03-01 | 2024-03-03 | 2024-03-03 09:00 | T1 财新 |
| 消息 C | 2024-03-01 | 2024-03-03 | 2024-03-03 09:05 | T1 一财（转载） |
| 消息 D | 2024-03-01 | 2024-03-05 | 2024-03-05 20:00 | T0 公告 |

**验证点：**

1. **状态演化线排序：** 节点顺序应为 A(3/1) → B(3/3) → D(3/5)，消息 C 因 fingerprint 重复被去重；
2. **时间线折叠：** 若事件跨度 > 1 年，早期节点显示为"··· 2023年及更早 ···"；
3. **抓取时间 vs 披露时间：** 消息 D 抓取时间 20:00 晚于披露时间，节点展示以披露时间 3/5 为准；
4. **旧闻重发：** 若 3/10 再次抓取到消息 A 的转载，fingerprint 匹配后标记为"旧闻"，不参与状态更新。

| 步骤 | 动作 | 预期结果 |
|------|------|---------|

### TC-009: 边界时间处理

| 场景 | 输入 | 预期处理 |
|------|------|---------|
| 跨日公告 | 公告披露时间 23:50 | 显示为当日 23:50，"下一交易日"正确计算为次日 |
| 节假日 | 公告披露时间为春节长假期间 | "发生后 1 日"跳过节假日，取开市首日 |
| 时间倒流 | 抓取到 publish_time < event.created_at 的消息 | 允许归入事件，更新 event.created_at |
| 未来时间 | 消息 publish_time 为明天 | 标记异常，人工审核队列，不自动处理 |

## 三、合规边界测试

### TC-010: 投资建议红线检测

| 步骤 | 动作 | 预期结果 |
|------|------|---------|
| 1 | 检查所有 Face 卡片的 headline | 不含"买入""卖出""持有""加仓""减仓""目标价"等词汇 |
| 2 | 检查 Back 卡片 | 不含具体股价预测 |
| 3 | 检查 AI 对话回复 | 当用户问"我该买吗"，回复包含"我无法提供投资建议" |
| 4 | 检查通知文案 | 不含"建议买入"等表述，只描述事件状态变化 |

**自动化检测：**
```python
FORBIDDEN_WORDS = ['买入', '卖出', '持有', '加仓', '减仓', '目标价', '必涨', '稳赚']
def compliance_scan(text: str) -> bool:
    return not any(word in text for word in FORBIDDEN_WORDS)
```
